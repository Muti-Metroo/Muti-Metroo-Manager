# Muti Metroo Manager — Claude Code Instructions

**Documentation:** https://github.com/postalsys/Muti-Metroo-Manager/

## Muti Metroo (the agent)

**Source:** `../Muti-Metroo` (`github.com/postalsys/muti-metroo`)

Userspace mesh networking agent. Creates encrypted TCP tunnels over QUIC/HTTP2/WebSocket transports. Multi-hop routing with SOCKS5 ingress and CIDR-based exit routing. E2E encryption (X25519 + ChaCha20-Poly1305) — transit nodes can't decrypt payload.

### Agent Roles

- **Ingress** — SOCKS5 proxy entry point, looks up routes, opens streams to exit
- **Transit** — Relays frames between peers, can't decrypt payload
- **Exit** — Opens real TCP connections, advertises CIDR routes, handles DNS

### Key Concepts

- **Peers:** Long-lived connections via QUIC/H2/WS, auto-reconnect with backoff
- **Streams:** Multiplexed virtual connections (state machine: Opening→Open→HalfClosed→Closed)
- **Routes:** CIDR LPM + domain pattern matching, flood-propagated with hop-count TTL
- **Port forwarding:** ngrok-style endpoint (exit) + listener (ingress) keyed by routing key

### Agent HTTP API

Muti Metroo Manager proxies all of these via `/api/proxy/*`:

| Category | Endpoints |
|----------|-----------|
| Health | `/healthz`, `/ready` |
| Dashboard | `/api/topology`, `/api/dashboard`, `/api/mesh-test` |
| Remote | `/agents/{id}`, `/agents/{id}/shell` (WS), `/agents/{id}/file/upload`, `/agents/{id}/file/download`, `/agents/{id}/routes/manage` |
| Control | `/routes/advertise`, `/sleep`, `/wake`, `/sleep/status` |

`/routes/manage` supports `action: add | remove | list | set_comment | set_source_ip | set_interface`. `source_ip` binds outbound TCP for a route to a specific local IP (`net.Dialer.LocalAddr`); empty clears. `set_interface` selects the egress NIC for a route; empty clears. It is accepted on any platform — on Linux + root it pins the NIC via `SO_BINDTODEVICE`, elsewhere the agent binds a source address picked from that interface. The only rejected case is an explicit `source_ip` not assigned to the chosen interface unless the agent is Linux + root. Both are local-only and never advertised to peers.

### Agent Config (relevant to Muti Metroo Manager)

| Config key | Notes |
|------------|-------|
| `http.address` (default `:8080`) | The URL Muti Metroo Manager's `-agent` flag points to |
| `shell.enabled` + `shell.whitelist` | Must be enabled for ShellTab |
| `file_transfer.enabled` + `file_transfer.allowed_paths` | Must be enabled for FilesTab |
| `exit.enabled` + `exit.routes` | Controls route advertisements |
| `socks5.enabled` + `socks5.address` | Shown in InfoTab |

## Build & Run

```bash
# Full build (frontend + Go binary)
make build

# Frontend only (outputs to internal/webui/dist/)
make build-frontend

# Go binary only (outputs to build/muti-metroo-manager)
make build-go

# Dev mode — two terminals:
go run ./cmd/manager -addr :3000 -agent http://<agent>:8080
cd frontend && npm run dev   # Vite on :5173, proxies /api/proxy/* to :3000

# Clean all build artifacts
make clean
```

IMPORTANT: After frontend changes, you must rebuild **both** the frontend and the Go binary. The Go binary embeds `internal/webui/dist/` via `go:embed` — stale dist means stale UI.

## Formatting

Frontend JS/TS/CSS is formatted with Prettier (`frontend/.prettierrc.json`). Run
`cd frontend && npm run format` (or `npm run format:check` in CI). Enable the
Prettier pre-commit hook once per clone with `make hooks` (sets
`core.hooksPath=.githooks`); it formats staged `frontend/**/*.{ts,tsx,js,jsx,json,css,mjs}`.

## Theme (Tailwind v4 + FlyonUI)

The UI is built on Tailwind v4 and FlyonUI. There is no `tailwind.config.js`
and no separate CSS build step: `@tailwindcss/vite` compiles
`frontend/src/styles/app.css` as part of `npm run build`. `tailwindcss`,
`flyonui` and the iconify plugin are devDependencies only.

- `styles/app.css`, the single entry point (imported from `main.tsx`):
  Tailwind + FlyonUI plugins, the light/dark theme blocks, topology role
  colors, and base rules. It `@import`s the other four so Tailwind inlines
  everything into one stylesheet and one `@layer components` order.
- `styles/fonts.css`, GENERATED by `scripts/vendor-fonts.mjs`; the
  `@font-face` block for the self-hosted faces. Inlined here rather than
  linked from `index.html` so the browser needs no second blocking request
  before it can start fetching the fonts.
- `styles/layout.css`, app-shell geometry driven by `--agent-panel-width`
- `styles/ui.css`, the app's own component classes (dialog shell, `ui-empty`
  / `ui-hint` / `ui-error` panel states, `ui-chip`, `ui-table-frame`,
  `ui-popover`, managed-list rows, wizard rail). Keep it small: anything
  expressible as utility classes belongs in the markup, and anything FlyonUI
  already ships (`badge`, `status`, `dropdown-item`) belongs there.
- `styles/metro.css`, the topology SVG, which needs real CSS for stroke
  widths and dash animations

Two tokens are worth knowing: `--color-hairline` is the single divider weight
(`border-hairline` in markup, `var(--color-hairline)` in CSS), and
`--color-terminal` is the terminal surface, shared with the xterm palette that
`ShellTab` sets in JS. Muted text is one level, `text-base-content/70`, chosen
so it clears WCAG AA in both themes; do not reintroduce a lighter one.

**Palette.** Muti Metroo's own brand, taken from the docs site
(`../Muti-Metroo/docs/src/css/custom.css`): warm brown `#8d6539` on cream in light
mode, `#d0a36e` on near-black brown in dark. Dark is the default; the toggle
lives in the header and persists to `localStorage` under `mutiMetrooTheme`.
`index.html` carries a pre-paint script that must stay in step with
`util/theme.ts` (same key, same fallback order).

**FlyonUI role gotcha.** `neutral` is a *content-bearing* role, not a surface:
an uncoloured `.btn-soft` takes its foreground from it and hover tints mix
from it. In the dark theme it must therefore be a light value with a dark
`neutral-content`, mirroring FlyonUI's own dark theme. Setting it to a surface
colour makes those controls invisible.

**Icons** come from `@iconify-json/tabler` via `@iconify/tailwind4`, used as
`icon-[tabler--name]` on a sized `<span>`. FlyonUI's runtime JS is *not*
loaded, React owns every interactive component (dropdowns, dialogs, tabs), so
only FlyonUI's stylesheet is used.

**Fonts** (Inter for UI, JetBrains Mono for data) are self-hosted under
`frontend/public/fonts/`, not fetched from a CDN: Muti Metroo Manager often runs on an
isolated mesh with no route to the public internet. Both are SIL OFL 1.1;
`public/fonts/OFL.txt` ships the upstream license text alongside the binaries.
Regenerate with `node scripts/vendor-fonts.mjs` (run from anywhere; it rewrites
both `public/fonts/*.woff2` and the generated `src/styles/fonts.css`).

## Persistent State

Muti Metroo Manager keeps operator-editable state in a SQLite database named
`muti-metroo-manager.db`, written to the directory passed as `-data-dir`. The
default is OS-appropriate (`config.DefaultDataDir()` in
`internal/config/datadir.go`): `~/Library/Application Support/Muti-Metroo-Manager/`
on macOS, `/var/lib/muti-metroo-manager` for root on Linux, `$XDG_CONFIG_HOME/muti-metroo-manager`
otherwise on Linux, `%LOCALAPPDATA%\muti-metroo-manager` on Windows.

Tables (see `internal/store/migrations.go`, schema versioned via `PRAGMA user_version`):

- `settings` — key/value table; today holds `api_address` and
  `socks_address` overrides for the labels the UI shows. An empty value
  is deleted (frontend then falls back to `window.location.host`).
- `agent_notes` — per-agent operator metadata: free-form `note` plus an
  `icon` key (the icon catalog itself lives in the frontend; the backend
  just stores the chosen key, lower-case `[a-z0-9_-]{0,32}`). Rows where
  both fields are empty are deleted, not stored.

Future domains (saved searches, etc.) drop in as new tables behind their
own typed methods — the generic key/value table is not the extension
point.

The SQLite driver is `modernc.org/sqlite` (pure Go) so `CGO_ENABLED=0`
cross-builds keep working — don't switch to `mattn/go-sqlite3`.

## Optional Downloads Bundle

When a `muti-metroo-downloads-bundle.zip` (built by `bundle-downloads.sh`)
sits next to the binary — or is pointed at via `-downloads-bundle` —
the server exposes it under `/api/downloads/manifest` and
`/api/downloads/file/<name>`, and the frontend reveals the Downloads
tab. A missing file is the expected default (feature off, tab hidden,
no log noise). Pass `-downloads-bundle off` to suppress the lookup
entirely.

The bundle must be flat (no nested entries) and contain a
`manifest.json` whose `files[].name` matches an entry in the zip — see
`internal/downloads/downloads.go`. The frontend uses 200 vs 404 on the
manifest fetch to decide whether to show the tab.

## Key Conventions

### Proxy Pattern
All frontend API calls go to `/api/proxy/*`. The Go server strips the `/api/proxy` prefix and forwards to the agent URL. Two HTTP client timeouts: 30s (normal) and 30min (file upload/download paths).

### Polling Intervals
- Dashboard + topology: 5000ms (`POLL_INTERVAL`)
- Mesh test: 60000ms (`MESH_TEST_INTERVAL`)
- Sleep status: 10000ms (`SLEEP_POLL_INTERVAL`)

### State Management
Pure React hooks — no external state library. Agent capabilities are cached in a `useRef<Map>` to persist across re-renders without triggering them. Topology layout is memoized via content hash (`hashTopology()`).

### WebSocket Shell Protocol
Binary frames with 1-byte message type prefix (constants in `frontend/src/api/types.ts`, mirroring the agent's `internal/shell/messages.go`):

| Type | Value | Direction | Payload |
|------|-------|-----------|---------|
| META | 0x01 | Client→Agent | JSON: `{"command":"sh","tty":{"rows":N,"cols":N,"term":"xterm-256color"}}` (optional `args:[]`) |
| ACK | 0x02 | Agent→Client | Shell ready |
| STDIN | 0x03 | Client→Agent | UTF-8 keystrokes |
| STDOUT | 0x04 | Agent→Client | Shell output |
| STDERR | 0x05 | Agent→Client | Shell output (stderr) |
| RESIZE | 0x06 | Client→Agent | 4 bytes: uint16 BE rows + uint16 BE cols |
| SIGNAL | 0x07 | reserved | Defined for forward compatibility; not currently sent by the web UI |
| EXIT | 0x08 | Agent→Client | Shell process exited |
| ERROR | 0x09 | Agent→Client | JSON: `{"code":N,"message":"..."}` |
| STDIN_CLOSE | 0x0a | reserved | No payload; signals stdin EOF. Not sent by the web UI, which always allocates a PTY (the line discipline turns Ctrl+D into EOF) |

Error codes: `ERR_SHELL_DISABLED = 20`, `ERR_SHELL_AUTH_REQUIRED = 21`, `ERR_SHELL_INVALID_CREDS = 22`, `ERR_FILE_TRANSFER_DENIED = 12`.

## Shell Tab Gotchas

1. **xterm.css is required** — Without `import '@xterm/xterm/css/xterm.css'`, the DOM renderer shows garbage (`xterm-char-measure-element` visible). Always import it.
2. **Do NOT use CanvasAddon** — `@xterm/addon-canvas` v0.7.0 breaks cursor rendering with xterm v6.0.0. The DOM renderer works correctly.
3. **Echo loop prevention** — BusyBox PTYs echo terminal query responses back. Suppressed via CSI parser handlers for DSR (`n`), DA1 (`c`), DA2 (`>c`), and CPR (`R`). DSR responses are proxied back via `sendStdin()` for vi/ash cursor positioning. Belt-and-suspenders regex on `onData`: `/^\x1b\[[\?>]?[\d;]*[Rcn]$/`.

## Releasing

Day-to-day releases are automated via GitHub Actions using
[release-please](https://github.com/googleapis/release-please)
(`.github/workflows/release-please.yml`): land Conventional Commits on
master, release-please opens a release PR that bumps `VERSION` and
`CHANGELOG.md`, and merging it tags the release.

`release.sh` exists for a full binary release with cross-compiled
assets: the script bumps the version, cross-compiles binaries, and
creates a GitHub release with assets. Do not run it for routine work —
let release-please cut the tag first, otherwise the two version bumpers
race.

### Prerequisites

- `go`, `node`, `npm`, `jq`, `curl` (required)
- `upx` (optional — compresses Linux (amd64+arm64) and Windows amd64 binaries)
- `GITHUB_TOKEN` environment variable (GitHub API token with repo write access)

### How to Release (manual, binary assets)

```bash
# Patch release (default): 0.1.4 → 0.1.5
GITHUB_TOKEN=xxx ./release.sh

# Minor release: 0.1.4 → 0.2.0
GITHUB_TOKEN=xxx ./release.sh minor

# Major release: 0.1.4 → 1.0.0
GITHUB_TOKEN=xxx ./release.sh major
```

### What the Script Does

1. Reads current version from `VERSION` file, bumps it
2. Validates clean working tree and available tag
3. Builds the React frontend (`npm ci && npm run build`)
4. Cross-compiles Go binaries for 6 platforms (with embedded frontend via `go:embed`)
5. Optionally compresses binaries with UPX
6. Generates SHA256 checksums
7. Commits version bump, creates annotated git tag, pushes both
8. Creates GitHub release with retry logic
9. Uploads all binaries + checksums as release assets
10. Verifies the release

### Build Targets

- darwin/arm64 (macOS Apple Silicon)
- darwin/amd64 (macOS Intel)
- linux/amd64 (x86_64)
- linux/arm64 (ARM64)
- windows/amd64 (x86_64)
- windows/arm64 (ARM64)

Linux (amd64+arm64) and Windows amd64 binaries are compressed with UPX. Darwin binaries are not (UPX breaks macOS code signing); Windows arm64 is also skipped.

### Version Management

- Version is stored in `VERSION` file at the project root
- `VERSION` is bumped by release-please's release PR (or by `release.sh` for a manual binary release) — do not edit it manually
- Git tags follow the format `v{VERSION}` (e.g., `v0.2.0`)

**Binaries location**: https://github.com/postalsys/Muti-Metroo-Manager/releases

## Common Tasks

### Add a new API endpoint
1. Add the function in `frontend/src/api/client.ts`
2. Add any new types in `frontend/src/api/types.ts`
3. Call from the appropriate component — the Go proxy forwards everything under `/api/proxy/*` automatically

### Add a new AgentPanel tab
1. Create `frontend/src/components/AgentPanel/NewTab.tsx`
2. Add the tab id to the `AgentPanelTab` union in `frontend/src/router.ts` and to the `tabs` array in `AgentPanel.tsx` (follows `info | routes | forwards | peers | shell | files | ping` pattern)
3. If the tab requires a capability check, add to `AgentCapabilities` type and check in the tab button's `disabled` prop

### Add a new top-level (major) tab
1. Add the id to the `MajorTab` union and to `MAJOR_TABS` / `SUB_TABS` / `DEFAULT_SUB_TAB` in `frontend/src/router.ts`
2. Add an entry to `MAIN_TABS` in `App.tsx` and render the tab body inside the `visibleActiveTab === 'newtab'` branch
3. If visibility is conditional (like Downloads), filter `visibleTabs` accordingly and add a redirect-away effect for the case when the tab disappears

### Modify the shell binary protocol
1. Update constants in `frontend/src/api/types.ts` (must match agent's `internal/shell/messages.go`)
2. Update handler logic in `ShellTab.tsx`

### Add a persisted setting or per-agent metadata field
1. Extend `Settings` (or `AgentMeta`) in `internal/store/store.go` and the matching TypeScript type in `frontend/src/api/types.ts`
2. Append a migration to `internal/store/migrations.go` (the slice index + 1 is the target `user_version`)
3. Wire reads/writes through the existing `/api/settings` or `/api/agent-meta/{id}` handlers — the store enforces validation
